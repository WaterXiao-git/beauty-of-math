# 1\. 产品定位、首期范围与边界

## 1\.1 产品定位

“数韵之美”是面向数学学习和课堂演示的智能交互式可视化平台。用户既可以按课程、章节和知识点进入，也可以直接使用自然语言提出问题。系统将公式、图形、参数、教学步骤和解释同步联动，使抽象数学对象能够被观察、操作和讨论。

首期不是制作若干互不关联的动画页面，而是建立一套可持续扩展的知识点生产与展示机制：我方持续提供经过审核的知识点内容，合作方根据统一内容规范构建表单、模板和运行系统。

## 1\.2 首期必须打通的能力

| 能力域           | 首期结果                                                     |
| ---------------- | ------------------------------------------------------------ |
| 内容入口         | 支持课程—章节—知识点选择，也支持自然语言提问进入。           |
| 知识点匹配       | 区分高、中、低置信度，分别采用直接加载、候选确认或安全回退。 |
| 交互教学         | 知识点页面具备数学可视化、参数控制、步骤播放、公式和解释联动。 |
| 上下文记忆与问答 | AI 读取用户历史会话，结合提问的知识点、函数、参数、步骤和选中对象后渲染和回答。 |
| 内容生产         | 我方按知识点内容整理规范整理知识点；合作方据此构建表单和发布流程。 |
| 状态与复现       | 同一知识点内容版本和实现版本能够稳定复现，关键修改可追踪、可回退。 |

## 1\.3 设计原则

1. 首次进入先显示经过审核的正确默认案例，再允许用户探索。

2. 同类知识点保持一致的页面布局与交互语言，但不得因复用组件删减关键数学内容。

3. 我方提供知识点内容、展示语义和验收要求；合作方负责表单、模板、组件和工程实现。

4. 任何异常都应可解释、可回退、可重置，不能留下不可恢复的展示状态。

## 4\.1  示例1：ε\-δ 极限定义

| 项目       | 需求                                                         |
| ---------- | ------------------------------------------------------------ |
| 教学目标   | 把“x 趋近 a 时 f\(x\) 趋近 L”转换为纵向 ε 误差带和横向 δ 邻域，使用户看到 ε 收紧时可行 δ 如何变化。 |
| 默认案例   | 默认 f\(x\)=x²、a=1、L=1、ε=0\.60；可切换 sin x 和 √x。系统给出一个安全的可行 δ，并明确 δ 不唯一。 |
| 画布与交互 | 显示函数曲线、目标点、L±ε 横带、a±δ 竖带和辅助线。步骤为：观察目标点→给定 ε→寻找 δ→验证定义。 |
| 边界       | 只在定义域内采样；δ 过小时仍需可见并显示数值；不得把数值搜索结果描述为唯一或最大 δ。 |
| 完成判定   | 最终步骤中 δ 范围内的有效曲线全部落入 ε 带；ε 与 δ 联动正确；不同案例无状态残留；极端参数不产生 NaN。 |

## 4\.2 示例2：导数的几何意义

| 项目     | 需求                                                         |
| -------- | ------------------------------------------------------------ |
| 教学目标 | 通过固定点 P 和移动点 Q，让用户观察 h 趋近 0 时割线斜率趋近切线斜率，理解差商极限与导数。 |
| 数学对象 | 函数曲线、P\(x₀,f\(x₀\)\)、Q\(x₀\+h,f\(x₀\+h\)\)、割线、P 点切线、Δx=h、Δy 和斜率数值。 |
| 交互过程 | 调节 x₀ 和 h，Q 沿函数曲线移动。步骤为：选取两点→显示割线与差商→减小 h→割线趋近切线。 |
| 边界     | h 不能等于 0；极小 h 时标签应自动简化；需说明左右差商；差商与切线斜率必须来自同一函数和同一 x₀。 |
| 完成判定 | 割线斜率与两点差商一致；h 减小时视觉差距和数值误差同步减小；重置恢复默认；AI 引用当前 h 和两种斜率。 |

## 4\.3 示例3：罗尔定理

| 项目       | 需求                                                         |
| ---------- | ------------------------------------------------------------ |
| 教学目标   | 不只展示水平切线，还要通过条件开关说明连续、可导、端点等高三个前提与结论之间的关系。 |

# 5\. 系统实现与工程边界

## 5\.1 内容与实现分工

我方提供知识点整理、独立效果预览和验收要求。合作方负责构建表单、存储字段、匹配模板、复用组件、转换内部配置、实现运行时和完成测试。合作方内部采用何种技术 Spec，可在详细技术设计中自行定义，但必须能完整承接 我方提供的知识点内容整理信息。

## 5\.2 模块责任

| 模块               | 负责                                           | 不得承担                                 |
| ------------------ | ---------------------------------------------- | ---------------------------------------- |
| 前端页面           | 输入、布局、状态展示和用户操作                 | 不得直接使用未经校验的模型输出执行代码。 |
| 智能路由 / 大模型  | 理解意图、召回知识点、组织解释和候选建议       | 不得作为数学正确性的唯一来源。           |
| 数学与规则引擎     | 解析、采样、求导、求积、求根、定义域和条件校验 | 不得伪造未支持对象的结果。               |
| 统一渲染运行时     | 绘制曲线、平面/立体图形、处理交互和动画        | 不得在单个页面中写死所有知识点内容。     |
| 内容表单与发布服务 | 承接 SYV\-Content、审核状态、版本和发布        | 不得擅自改变已冻结内容的数学含义。       |

## 5\.3 安全与稳定性

| 领域       | 强制边界                                                     |
| ---------- | ------------------------------------------------------------ |
| 表达式安全 | 使用安全数学解析器，不使用 eval；限制长度、嵌套、函数白名单和计算时间。 |
| 模型安全   | 用户输入、提示词和系统配置隔离；模型输出始终按不可信输入处理。 |
| 渲染安全   | 限制采样数、图层数、动画复杂度和 3D 资源；异常时降级而非卡死。 |
| 密钥与数据 | 模型密钥不得下发前端；不同环境数据和密钥隔离；管理修改保留审计记录。 |
| 可维护性   | 知识点逻辑不得只写在页面或提示词中；内容、模板、接口和实现版本可追踪。 |

## 5\.4 推荐性能基线

以下数值为首期评审建议，正式目标应在设备、网络、并发和技术栈确定后由双方冻结。

| 指标               | 建议基线                            |
| ------------------ | ----------------------------------- |
| 预制页面首屏可交互 | 不高于 3 秒                         |
| 二维参数更新反馈   | 不高于 100 毫秒                     |
| 二维动画           | 不低于 50 FPS                       |
| 三维动画           | 不低于 30 FPS（代表性设备）         |
| 常规数学验证       | 不高于 2 秒                         |
| 动态生成或复杂路由 | 15 秒内完成，或持续返回明确阶段状态 |
